# Bitkub 시세 알림 · 김치 프리미엄 대시보드

Bitkub(태국) 거래소 시세를 원화로 환산해 Telegram으로 알려주고, 같은 코인의 Bithumb(한국) 가격과 비교해 김치 프리미엄을 한 화면에 보여줍니다.

- **Telegram 알림**: 급등 알림(구간 저점 대비 상승률), 정기 시세(THB 가격과 원화 환산가, 빗썸 가격, 김프)
- **김프 대시보드**: 두 거래소 공통 코인 전체의 김프(%) 요약, 분포, 코인별 표, 최근 급등 알림

외부 패키지 없이 Node.js만으로 동작합니다. `npm install`이 필요 없습니다.

## 빠른 시작

Node.js 20 이상이 필요합니다 (`node -v`).

```bash
cd bitkub-monitor
cp .env.example .env
```

1. Telegram에서 [@BotFather](https://t.me/BotFather)에게 `/newbot`을 보내 봇을 만들고, 받은 토큰을 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣습니다.
2. 만든 봇에게 아무 메시지나 보낸 뒤 채팅 ID를 확인해 `TELEGRAM_CHAT_ID`에 넣습니다. 그룹에서 받으려면 봇을 그룹에 초대한 직후 실행하거나, 그룹에서 `/start`를 보낸 뒤 실행합니다. 봇은 기본 설정(프라이버시 모드)에서 그룹의 일반 메시지를 받지 못하므로, 이미 들어가 있는 봇이면 `/start`를 보내거나 봇을 내보낸 뒤 다시 초대하세요. 일반 그룹이 슈퍼그룹으로 바뀌면 채팅 ID도 바뀌니 로그에 안내가 나오면 다시 확인합니다.
   ```bash
   npm run telegram:chat-id
   ```
3. 테스트 메시지로 연결을 확인합니다.
   ```bash
   npm run telegram:test
   ```
4. 실행합니다. 대시보드는 http://127.0.0.1:8080 입니다.
   ```bash
   npm start
   ```

Telegram 설정 없이 실행하면 알림은 콘솔에만 출력되고 대시보드는 그대로 동작합니다.

## 알림 예시

급등 알림 (같은 주기에 감지된 코인은 한 메시지로 묶어 보냅니다)

```text
[급등 알림] 2종목

BR 베드록
5분 저점 대비 +3.44%
현재 ฿17.83 ≈ ₩713.4
저점 ฿17.24 (4분 전)
24h +7.97% · 거래대금 ₩26.5억
빗썸 ₩712 · 김프 -0.20%

SOSO SoSoValue
5분 저점 대비 +3.47% · 30분 저점 대비 +7.12%
현재 ฿12.35 ≈ ₩494.3
저점 ฿11.53 (21분 전)
24h +8.20% · 거래대금 ₩7.7억
```

정기 시세 (기본 60분마다, 매시 정각)

```text
[시세] Bitkub
환율 1 THB = 40.02 KRW (하나은행 고시)
김프 중앙값 +1.14% (이상치·저유동성 제외) · BTC +1.65% · USDT +1.60%

BTC 비트코인 ฿2,769,594 ≈ ₩110,839,137
24h -0.33% · 빗썸 ₩112,673,000 (김프 +1.65%)

ETH 이더리움 ฿83,589 ≈ ₩3,345,219
24h -2.27% · 빗썸 ₩3,400,000 (김프 +1.64%)
```

Bithumb에 없는 코인은 빗썸 가격과 김프 줄이 빠집니다. Bithumb 시세나 환율 갱신이 실패한 상태면 해당 줄 끝에 `(갱신 실패, 12분 전 값)`처럼 언제 값인지 붙습니다.

## 급등 판정

`SURGE_RULES=5m:3,30m:7`은 "최근 5분 저점 대비 +3% 이상" 또는 "최근 30분 저점 대비 +7% 이상"이면 알린다는 뜻입니다.

- 짧은 구간 규칙은 갑작스러운 펌핑을, 긴 구간 규칙은 완만하지만 큰 상승을 잡습니다. 구간은 `POLL_INTERVAL_SEC`보다 길어야 하며, 짧으면 시작할 때 설정 오류로 알려 줍니다.
- 판정 가격은 매수·매도 호가의 중간값입니다(호가가 없으면 체결가). 체결가만 보면 호가 사이를 오가는 체결 한 건에도 급등으로 잡히기 때문입니다. 알림의 "현재"와 "저점"도 이 값입니다.
- 같은 코인은 `SURGE_COOLDOWN_MIN`(기본 30분) 동안 다시 알리지 않습니다. 단, 직전 알림 가격보다 가장 작은 규칙의 %만큼 더 오르면 "추가 상승"으로 다시 알립니다. 대기 시간이 지나도 저점이 직전 알림 이전 그대로면(같은 상승의 연장) 마찬가지로 더 올라야 알립니다. 반대로 직전 알림의 저점보다 그만큼 더 낮은 새 저점에서 다시 올라 직전 저점 위로 회복하면 대기 중이라도 새 급등으로 알립니다(하락 중의 반등은 직전 저점을 넘지 못하므로 알리지 않습니다).
- Bitkub 24시간 거래대금이 `SURGE_MIN_VOLUME_THB`(기본 ฿500,000) 미만인 코인은 체결 몇 건에도 가격이 튀므로 알리지 않습니다. `WATCHLIST`에 적은 코인도 같은 기준을 적용하며, 시작할 때 제외되는 코인이 있으면 시작 알림과 로그에 경고가 나옵니다.
- 가격 기록은 메모리에만 있어서 재시작 직후에는 기록이 쌓일 때까지(최대 규칙 구간만큼) 판정 범위가 짧습니다.

## 김치 프리미엄 계산

```text
김프(%) = (Bithumb 원화 가격 ÷ (Bitkub THB 가격 × THB→KRW 환율) − 1) × 100
```

양수면 한국(Bithumb)이 비싸고, 음수(역프)면 태국(Bitkub)이 비쌉니다. 가격은 각 거래소의 마지막 체결가입니다.

대시보드에서 환율 기준을 고를 수 있습니다.

| 기준 | 환율 | 의미 |
|---|---|---|
| 은행 고시 (기본) | 하나은행 매매기준율 | 일반적인 김프. USDT 프리미엄(원화 자금 유입)까지 포함 |
| USDT 교차 | Bithumb USDT 원화 가격 ÷ Bitkub USDT 바트 가격 | 스테이블코인 기준. 은행 기준 김프에서 USDT 프리미엄을 뺀 코인 자체의 가격 차이 |

표시 기준

- **이상치**: 김프 절댓값이 `OUTLIER_PCT`(기본 30%) 이상. 이름만 같은 다른 코인이거나 입출금이 막힌 경우가 대부분이라 요약 통계와 분포에서 기본으로 뺍니다. 필터의 "이상치 포함"으로 볼 수 있습니다.
- **저유동성**: Bitkub 24시간 거래대금이 `LOW_LIQUIDITY_THB`(기본 ฿100,000) 미만이거나 Bithumb 24시간 거래대금이 `LOW_LIQUIDITY_KRW`(기본 ₩4,000,000) 미만. 마지막 체결가가 오래됐을 수 있어 김프가 실제와 다를 수 있으므로 표에는 보이지만 요약 통계(중앙값, 김프/역프 수)에서는 뺍니다.
- **거래정지**: Bitkub에서 매수 또는 매도가 정지된 코인. 요약 통계에서 뺍니다.
- **유의**: Bithumb 투자유의 지정 종목.
- Bithumb에 KRW 마켓이 없는 Bitkub 코인은 비교할 수 없어 표에 없고, 표 머리말에 몇 개인지만 보여 줍니다.

환율은 네이버 증권의 하나은행 고시 환율을 먼저 쓰고, 실패하면 Yahoo Finance, 그다음 ExchangeRate-API(하루 1회 갱신) 순으로 시도합니다. 네이버·Yahoo 주소는 공식 API가 아니어서 예고 없이 바뀔 수 있습니다. 모두 실패하면 마지막으로 받은 환율을 계속 쓰고 대시보드 상단과 Telegram 메시지에 갱신 실패와 언제 값인지 표시합니다. 대시보드의 환율 기준 버튼에는 실제로 쓰인 소스 이름이 나옵니다. `FX_THB_KRW`에 값을 넣으면 고정 환율을 씁니다.

## 설정

모든 항목과 설명은 [`.env.example`](.env.example)에 있습니다. 자주 바꾸는 항목만 정리하면 다음과 같습니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `SURGE_RULES` | `5m:3,30m:7` | 급등 규칙. `off`면 급등 알림 끔 |
| `WATCHLIST` | (전체) | 급등 감시 코인 제한. 예: `BTC,ETH,XRP` (`KRW-BTC`, `BTC_THB`처럼 적어도 됨) |
| `REPORT_INTERVAL_MIN` | `60` | 정기 시세 간격(분). 프로그램을 실행하는 서버의 시간대 기준으로 `60`이면 매시 정각, `1440`이면 매일 0시. `0`이면 끔, 최대 `10080`(1주). 서버 시간대가 UTC면 `TZ=Asia/Seoul`을 주세요 |
| `REPORT_SYMBOLS` | `BTC,ETH,XRP,SOL,DOGE,USDT` | 정기 시세에 넣을 코인. `all`(Bitkub THB 전체), `common`(빗썸에도 있는 코인), `top:20`(거래대금 상위 20)을 쓰거나 섞을 수 있음 |
| `POLL_INTERVAL_SEC` | `15` | 시세 조회 간격(초) |
| `DASHBOARD_HOST` / `DASHBOARD_PORT` | `127.0.0.1` / `8080` | 대시보드 주소 |

`.env` 대신 환경 변수로 넣어도 되며, 환경 변수가 우선합니다.

## 상시 실행

알림을 계속 받으려면 프로세스를 띄워 둬야 합니다. 서버나 항상 켜 두는 PC에서 pm2를 쓰는 예입니다.

```bash
npm install -g pm2
TZ=Asia/Seoul pm2 start src/index.js --name bitkub-monitor   # 서버 시간대가 UTC인 VPS에서는 TZ를 꼭 주세요
pm2 save
pm2 startup   # 출력되는 명령을 실행하면 재부팅 후에도 자동 시작
```

다른 기기에서 대시보드를 보려면 `DASHBOARD_HOST=0.0.0.0`으로 바꿉니다. 인증 기능이 없으므로 인터넷에 공개할 때는 방화벽이나 리버스 프록시 인증을 함께 설정하세요.

## 구조

```text
src/
  index.js              진입점: 설정 읽기, 모니터와 대시보드 서버 시작
  monitor.js            수집 주기, 급등 감지, 정기 시세, 대시보드용 스냅샷
  sources/bitkub.js     Bitkub 시세·코인 목록 (api/v3)
  sources/bithumb.js    Bithumb 시세·마켓 목록 (v1)
  sources/fx.js         THB→KRW 환율 (네이버 → Yahoo → ExchangeRate-API)
  market.js             김프 계산, 이상치·저유동성 표시, 요약
  surge.js              급등 판정과 재알림 대기
  telegram.js           Telegram 전송 (429 재시도, 긴 메시지 분할)
  messages.js           알림 메시지 형식
  server.js             대시보드 HTTP 서버 (/, /api/snapshot, /healthz)
  tools/                chat-id 확인, 테스트 메시지 전송
public/index.html       대시보드 화면 (단일 파일)
test/                   단위·통합 테스트 (npm test, 네트워크 불필요. 거래소·Telegram 응답은 가짜 fetch로 재현)
```

## 참고

- 이 도구는 시세 확인용이며 투자 판단의 책임은 사용자에게 있습니다. 김프가 크게 벌어진 코인은 입출금 중단, 다른 네트워크, 동명이종 코인인 경우가 많으니 거래소 공지를 확인하세요.
- Bitkub 변동률은 최근 24시간, Bithumb 변동률은 거래소가 제공하는 전일 종가 대비(`signed_change_rate`)입니다.
- `/healthz`는 Bitkub 시세가 조회 간격의 4배(최소 60초) 넘게 끊기면 503을 돌려줍니다(첫 Bitkub 조회에 성공할 때까지도 503). 거래소 장애를 알리는 모니터링·알림 용도이며, 프로세스를 재시작해도 거래소 장애는 풀리지 않고 재시작마다 시작 알림이 다시 가므로 자동 재시작 조건으로는 쓰지 마세요.
- Bithumb가 특정 마켓의 시세를 거절하면(상장폐지 직후 등) 그 마켓만 빼고 계속 받다가 다음 마켓 목록 갱신(1시간) 때 다시 포함합니다.
- 기본 설정에서 Bitkub는 15초마다 1회, Bithumb는 3회(코인 100개씩) 요청합니다. 두 거래소 공개 API 제한보다 훨씬 적습니다.
- 회사망처럼 HTTP 프록시를 거쳐야 하는 환경이라면 Node.js 22.21 이상에서 `NODE_USE_ENV_PROXY=1 npm start`로 실행하면 `HTTPS_PROXY` 설정을 따릅니다.
